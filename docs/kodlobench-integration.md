# KodloBench: структура розділу та підключення даних

Публічний інтерфейс результатів тестування моделей ШІ. Методологія, завдання, критерії й формули оцінювання сюди не входять: сайт показує лише ті поля, які власник явно підготував до публікації.

## Адреса і навігація

- `/kodlobench` — єдина сторінка розділу. Стан у адресі: `?category=<id>` та необов’язкові `q`, `model`, `agent`, `sort`, `dir`, `log`, `only`, `sel`, `open`. Будь-який вигляд можна надіслати посиланням, `Назад` повертає попередню категорію.
- Навігація: верхнє меню (від ширини `xl`, на вужчих екранах пункт доступний через «Тулзи»), мобільне меню, картка в «Тулзи», підвал, `sitemap.xml`.
- Вкладки (`lib/kodlobench/categories.ts`): `overall` (за замовчуванням), `pdrbench-pro`, `redotui-bench`, `utwmr-rec-bench`, `3dsc-gt-plus`.

## Екрани

1. Вкладки «Загальний» + чотири категорії (клавіатура: стрілки, Home, End) і короткий підпис активної.
2. Панель керування: пошук, фільтри моделей і агентів, «Лише обрані», скидання. Обрані записи завжди видимі.
3. Лоток порівняння: до 8 записів із закріпленими слотами кольору. Колір належить запису, а не його місцю в рейтингу, і не змінюється від фільтрів чи сортування. Номер слота дублює колір.
4. Графіки йдуть один під одним, без перемикання: «KodloBench Intelligence Index» (для категорії — «<назва>: бали») у вигляді стовпців за спаданням балу, далі точкові «Бал і вартість», «Бал і час», «Бал і токени». Стовпці мають колір сімейства моделі, значення всередині, логотип лабораторії й нахилену назву під стовпцем. На точкових графіках біля кожної точки підписано модель (підписи розставляються без накладань, `lib/kodlobench/labels.ts`); логарифмічну шкалу осі X вмикають окремо для кожного графіка (`?log=cost,time`).
5. Таблиця: модель, CLI-агент, конфігурація, бал, час, токени, вартість. Сортування по всіх колонках, пошук. Різні конфігурації однієї моделі — окремі рядки з позначкою конфігурації.
6. Деталі результату (`<dialog>`): усі опубліковані поля, додаткові показники, примітки, матеріали.

Єдиний стан наведення/фокусу й вибору спільний для всіх графіків і таблиці: наведений запис підсвічується скрізь, обраний має свій колір і номер скрізь.

## Загальний бал

Рахується на сервері (`lib/kodlobench/overall.ts`), у файл даних не записується. Формула: сума балів чотирьох категорій, коефіцієнт кожної 1; максимум категорії 550, разом 2200. На сторінці показується `сума / 100` з двома знаками: 2200 → `22,00`. Бали окремих категорій показуються як у файлі, без ділення.

- Рядок «Загальний» є лише для конфігурації (модель + агент + конфіг), яка має рівно один запис із балом у кожній із чотирьох категорій. Якщо категорії або балу немає, загального балу теж немає: пропуск не рахується як 0. Справжній 0 враховується.
- Час, токени й вартість у цьому рядку — суми по чотирьох категоріях; якщо хоч однієї складової немає, сума відсутня («Немає даних»).
- Складові балу видно в деталях запису.
- Щоб загальний бал склався, модель, агент і конфігурація мають збігатися в усіх чотирьох записах.

## Стани

| Стан | Що бачить відвідувач |
|---|---|
| Завантаження | `loading.tsx` (скелетон), скелетон графіка під час підвантаження Recharts |
| Результатів немає | «Результати KodloBench ще не опубліковані.» Вкладки лишаються видимими |
| Є результати, але немає повного набору з чотирьох | «Загальний бал поки не можна показати.» |
| У категорії немає записів | «Для {назва} результати ще не опубліковані.» |
| Фільтри нічого не знайшли | повідомлення й кнопка скидання |
| Помилка даних | повідомлення й «Спробувати знову» (`router.refresh`); виняток у рендері ловить `error.tsx` |
| Значення відсутнє | «Немає даних» (штрихований трек у стовпчиках). Реальний `0` показується як `0` |

## Підключення даних

Єдине джерело — файл `content/kodlobench/published.json`, який власник готує й комітить явно. Сайт читає лише цей файл (`lib/kodlobench/source.ts`), нічого не шукає, не сканує й не імпортує.

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-01-31",
  "currency": "USD",
  "results": [
    {
      "id": "model-x-agent-y-high",
      "category": "pdrbench-pro",
      "model": "Назва моделі",
      "agent": "Назва CLI-агента",
      "config": "high",
      "score": 0,
      "timeSeconds": 0,
      "tokens": 0,
      "cost": 0,
      "publishedAt": "2026-01-31",
      "metrics": [{ "label": "Показник", "value": 1, "unit": "од." }],
      "notes": "Текст примітки",
      "media": [{ "kind": "image", "url": "https://…", "alt": "Опис" }]
    }
  ]
}
```

Правила (`lib/kodlobench/validate.ts`):

- Дозволені лише перелічені поля; будь-які інші ключі відкидаються й до браузера не потрапляють.
- `id` унікальний, `[a-z0-9._-]`; це ключ, який розрізняє конфігурації однієї моделі.
- `agent`, `config`, `score`, `timeSeconds`, `tokens`, `cost` можна пропустити або поставити `null`: це «Немає даних», не нуль.
- `cost` вимагає `currency` (код ISO 4217) на рівні файлу. Шкала балу не припускається: вісь береться з даних.
- `media` приймає лише `https`; зображення, відео чи посилання з’являються тільки якщо власник їх додав.
- Недійсні записи приховуються й лічаться (у логах сервера); недійсна «обгортка» файлу показує стан помилки.
- Ідентифікатори з префіксом `synthetic-` у публічному файлі не приймаються.

Публікація: змінити файл → PR → розгортання. Перехід на іншу схему зберігання (наприклад, таблицю Supabase) вимагає лише заміни `loadPublishedFile()` у `source.ts`: сторінка й компоненти отримують ті самі поля. Мінімум для цього: міграція `supabase/migrations/NNN_kodlobench.sql`, читання через `createAdminClient()` в `unstable_cache`, ті самі перевірки з `validate.ts`.

## Синтетичні дані для перевірки інтерфейсу

```bash
KODLOBENCH_SYNTHETIC=1 npm run dev
```

Працює лише коли `NODE_ENV !== "production"`. Сторінка показує смугу «Режим розробки», рядки й деталі позначені «синт.». Фікстури (`lib/kodlobench/fixtures.ts`) мають вигадані назви й не імпортуються у виробничому шляху. Тести перевіряють, що у виробництві прапорець ігнорується.

## Перевірка

```bash
npx vitest run lib/kodlobench   # валідатор, логіка вибору/сортування, джерело даних
npm run build
```

## Кольори й логотипи сімейств

`lib/kodlobench/families.ts` визначає сімейство за назвою моделі (GPT, GLM, Grok, Claude, Gemini, DeepSeek; решта — нейтральний сірий). Кожне сімейство має колір (`--kb-fam-*` у `globals.css`, окремі значення для світлої теми) і монохромний логотип лабораторії на прозорому фоні (`lib/kodlobench/family-logos.ts`, контури з LobeHub Icons, ліцензія MIT; знаки належать їхнім власникам і використані лише для впізнавання лабораторії). Щоб додати сімейство, додайте його до `FAMILIES`, колір до `globals.css` і контур логотипа до `family-logos.ts`.
